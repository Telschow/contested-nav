# navkit 0.2.0

> **DRAFT.** Not released. The package version still reads 0.1.0 and no tag exists. The maintainer
> approves the text, bumps the version and creates the tag.

navkit is a 21-state error-state Kalman filter and a calibration harness for navigation when GNSS is
denied. Everything runs on a deterministic synthetic fixture: **no real sensor data is evaluated and no
number here is a field measurement.** This is the first tagged release; 0.1.0 was never tagged.

## The result, unchanged

With GNSS denied for 15 s and visual aiding on, the filter is more accurate and wrong about it:
ATE 2.541 m against 3.782 m with vision off, while its claimed 1σ falls from 0.567 m to 0.161 m,
mean NEES is 419.4 against an expected 3, and 2σ coverage is 20.0% where 99.3% is expected. Visual
fusion therefore ships **off by default**. The overconfidence held at every outage window and seed
tried. The accuracy gain held only for outages that start early.

## What is new

**Measurement of what was assumed**
- `navkit sweep mismatch`: the filter is told sensor noise that is a factor of the true value.
  Assuming 20% to 30% less noise than the truth takes 2σ coverage below a 90% band, and below that
  the gate rejects healthy GNSS fixes. [Page](../mismatch.md).
- `navkit sweep faults`: eight fault modes against a clean control, with detection and false-alarm
  counts from the FDIR event log. The Track A exit test is **not met**: four of 18 fault cells are
  declared in every seed, and the healthy control with an outage declares a fault in 3 of 5 seeds.
  [Page](../faults.md).
- `navkit sweep outages` (outage start and duration), plus the existing seed and scene sweeps.

**A fix that moved four published rows**
- Every benchmark scenario now goes through the injection layer ([ADR-0012](../adr/0012-every-scenario-is-injected.md)).
  Before, `gnss_only`, `dead_reckoning`, `vision_anchor_in_measurement_noise` and `vision_only` ran with
  a noiseless IMU. Their ATE moves by 0.003 m to 0.371 m, no verdict changes, and the three outage
  cases and the headline are bit-identical.

**Engineering you can check**
- Golden snapshot test, property tests and an analytic IMU, so results agree across Linux, macOS and
  Windows within stated tolerances ([ADR-0009](../adr/0009-cross-platform-numerics.md)).
- CI: lint, mypy, tests on Python 3.11 to 3.13, a coverage ratchet, reproducibility jobs, a wheel
  install check, a container build, CodeQL, secret scan including history, dependency review,
  `pip-audit`, a CycloneDX SBOM, link checks, and a strict documentation build.
- `scripts/check_srs_trace.py`: every requirement and acceptance criterion has a test, a checked
  configuration value or a declared gap.
- A MkDocs Material site with an API reference, a model contract (`docs/MODEL.md`), twelve ADRs, a risk
  register and a RICE-ordered roadmap with a stability check. The README is 129 lines.
- `make` targets, pre-commit hooks, a Dockerfile and a devcontainer.

## Upgrade notes

- If you quote the four cases above, re-read them. The golden snapshot was regenerated for exactly
  these four.
- New estimator keys `gnss_sigma_scale` and `vision_sigma_scale` default to 1 and change nothing.
- `docs/index.html` and the 11 MB `demo.html` are gone. The demo now runs the benchmark case.

## Known limits

- Synthetic data only. Nothing is validated against hardware.
- The headline defect is not fixed. A structural remedy (P5-03) was deliberately not attempted.
- Four findings about the model are recorded and unfixed: inert bias sigmas, drift keys named per
  second that are per square-root second, one initial bias sigma for two units, and no velocity
  process noise. See the [model contract](../MODEL.md) and the open issues.
- Detection is measured with five seeds. That cannot show a 95% rate in any case.
- The filter is overconfident under visual aiding, and a modest spoof after an outage is not
  detected beyond the control's false alarms ([ADR-0007](../adr/0007-spoof-permanence-hysteresis.md)).
